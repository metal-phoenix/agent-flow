# Agent Flow line-by-line audit — 2026-11-17

Audit of metal-phoenix/agent-flow at the point it was forked from patoles/agent-flow
(commit `3489e17`), before any "make it ours" changes. Performed per-directory by
parallel reviewers, spot-checked and verified against the actual source and
`pnpm audit` output by the author of this document. All line numbers refer to the
pre-fork tree; several of the HIGH items below have since been fixed on this branch
(noted inline) — this file records what was found, not just what remains.

## Verdict

**Overall: safe to self-host, with two real issues that this fork fixes.**

The project is a well-built local dev tool: HTTP/WS servers bind to loopback only,
have an explicit DNS-rebinding guard (`extension/src/request-guard.ts`), validate
request origins, and use atomic (temp-file-then-rename) writes everywhere they touch
`~/.claude/settings.json` or discovery files. No `eval`, no shell string
interpolation, no obvious injection vectors. The two things worth forking over were:

1. **Telemetry was opt-out, not opt-in**, and shipped a hardcoded third-party
   (Supabase) endpoint and key baked into the published binary. Fixed: removed
   entirely in this fork (see `docs/../CHANGELOG.md`).
2. **Hooks were installed into `~/.claude/settings.json` unconditionally** on every
   `npx agent-flow-app` run, with no opt-out flag. Fixed: now opt-in
   (`--setup-hooks` / `AGENT_FLOW_SETUP_HOOKS=true`).

Everything else below is either already fine (loopback binding, path traversal
guards, atomic writes) or a dependency-version issue fixed by a version bump.

## Low-risk / informational findings (no action needed)

- **Loopback binding + DNS-rebinding guard**: `extension/src/request-guard.ts`'s `isLoopbackHost()` rejects any request whose `Host` header isn't `127.0.0.1`/`localhost`/`[::1]`, closing the classic "webpage POSTs to your loopback dev server" and DNS-rebinding holes. Used consistently by the hook server, dev relay, and standalone app server.
- **Hook request auth**: `isAllowedHookRequest()` rejects any request carrying an `Origin` header (browsers always send one on cross-origin POST; Node's `http` client, which is all `hook.js` ever uses, never does) — an effective, if implicit, authentication check for a server with no token.
- **Path traversal guards**: `app/src/static.ts` uses `path.basename()` + a `startsWith()` containment check before serving any file; `extension/src/session-watcher.ts` / `session-relocation.ts` constrain all reads to known Claude/Codex project directories.
- **Child processes**: all of them run a static, non-parameterized command (`command -v node` / `where node` to resolve the Node binary for the hook script; `open`/`xdg-open`/`start` to open the browser with a `127.0.0.1` URL). No user input reaches any shell.
- **No `eval`/`new Function`/dynamic `require`** anywhere in the codebase.
- **Web UI (`web/`)**: pure client-side rendering, no telemetry, no analytics, no `dangerouslySetInnerHTML` on agent-provided content, no filesystem access. Only network activity is the SSE connection to the local relay (`127.0.0.1:<port>/events`) and (dev-mode only) `postMessage` with the VS Code webview bridge.
- **VS Code extension (`extension/`)**: hook server and discovery file writes are all loopback-scoped and confined to `~/.claude/`; `uninstall.js` correctly removes only Agent Flow's own hook entries, preserving other tools' hooks in the same `settings.json`.
- **CI (`.github/workflows/ci.yml`)**: runs on `pull_request` (including from forks) but only installs deps, runs tests, and typechecks — no secrets referenced, no deploy/publish step. GitHub Actions are pinned to major-version tags (`@v4`) rather than SHAs, which is a minor supply-chain hardening opportunity but not unusual.

## What this fork changed as a result

See the "metal-phoenix fork" section of `README.md` and the dated entry in
`CHANGELOG.md` for the full list. In short: telemetry removed (not disabled),
hooks made opt-in, transcript roots and bind address made configurable via env
vars, vulnerable dependencies bumped, and a Dockerfile added.
